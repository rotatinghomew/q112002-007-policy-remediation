# 课堂规范执行简报：口径与裁定规则

本文件是 `briefing/` 引擎的业务口径说明，所有数字以业务日（整数日）为时钟，
统计单位是**学生 × 原任务**配对。重开只延长原登记的观察，不产生新任务、新分母。

## 1. 规范适用

1. **基线选择**：任务按首次开放日 `opened` 选择同年级、同任务类别中
   `effective <= opened` 的最新规范。重开不改变适用规范。
2. **例外文件的两个时间**：
   - `approval_day` 是文件写明日期，`received` 是督导实际收到日期。
   - 只有 `received <= as_of` 的文件才能作为当日执行依据；迟到的批准在到达前
     不产生豁免效力，到达后按**规范改判**处理，不追溯改写教师前期结论。
   - `cancels` 指向的撤销文件本身也必须已收到，才解除原文件。
3. **冲突处理**：同一任务存在多份均有效、指向不同规范且无撤销/裁定的文件时，
   适用状态为 `conflict`。冲突期间：
   - 不确定事项**不得记为教师失误**，也**不得把班级伪装成全数达标**；
   - 该任务配对整体退出确定口径的分子分母，待办以「待确认（批准文件冲突）」
     照常发给任课老师，等待发文单位确认；
   - 撤销或裁定到达后恢复确定口径，冲突解除本身计入「规范改判」依据。
4. **口径冻结**：观察期一旦结束，配对按**观察期结束当日有效**的规范归并。
   之后到达的文件只能产生撤回/解除，不能把历史分子分母搬到新口径，
   也不能抹除已经发生的步骤或补救记录。

## 2. 观察期与步骤履行

- 首次观察期 `[opened, due]`，长度 `L = due - opened`。
- 重开后只有一条连续观察期 `[opened, reopened + L]`；重开日之后的步骤与首次
  开放同等计入按时，但晚于新截止日仍属超期。
- 步骤以 `happened`（行为发生日）判断是否在观察期内；`received` 更晚只是补传，
  **补交一份草稿不能把原任务报告为按时完成**。同一配对同一步骤取最早 `happened`。
- 配对在 `as_of` 的状态：
  - `pending_observation`：观察期未结束，不进任何分母（未到观察点）；
  - `ok`：观察期已结束、口径确定、所有要求步骤按时；
  - `missing`：口径确定但存在缺失或超期（`late`）步骤，形成待跟进；
  - `uncertain`：当日规范冲突未解除，挂起等待确认。

## 3. 指标分母与公平比较

- 分母只包含**观察期已结束且适用要求确定**的配对；冲突与未到观察点一律排除。
- 指标按 `(政策, 年级, 任务类别, 步骤)` 分口径输出，每个口径自带分子、分母、
  比率和配对清单。
- 只有要求集合完全相同的口径之间才能做校际比较；**不得把不同口径的总量折线
  直接接起来**。规范改过的两周可以用当时有效要求重算历史执行率（引擎接受任意
  `as_of` 回溯），改判造成的口径缩小以独立的「规范改判」行呈现。

## 4. 补救（补办）与认领

1. **有效补救条件**（同时满足）：
   - 补做练习经 `makeup_options` 登记允许用于该原任务，学生在原任务名单内；
   - 独立完成日 `independent` 落在补办窗 `[start, end]`（含首尾）；
   - 提示日 `hint` 晚于独立完成日；`hint = null` 表示监考确认未提供提示，视同满足。
2. **一次补做只能认领一次明确允许的原任务**。
3. **竞争认领**：同一 `work` 被多位老师认领时，裁定前各方状态均为 `contested`，
   双方都不能结案。`rulings.granted` 指向的认领变为 `valid` 并解除对应待办，
   竞争方变为 `lost_ruling`，其班级事项仍需另行处理。
4. **缺陷认领**（窗口外、提示不晚于独立做、未登记允许、学生不在名单等）状态为
   `defective`，不能结案；已发生的补做保留在学生记录中。
5. **规范更正后的处理**：原任务不再要求某步骤时，相关待办以 `withdrawn_policy`
   撤回并注明依据文件；已经做过的补救不抹除、不自动挪去结另一项。
6. **两套指标分开**：补救只解除待跟进状态，原按期执行率的分子不增加；
   补救完成率 = 已补救解除的草稿待办 / 草稿缺失且要求未被撤回的待办总数，
   被撤回项不进补救口径。

## 5. 任课变动与通知

- `owners` 变动在 `effective` 当日开始生效（且文件已收到），之后待办按新老师归集。
- 已发出名单之后发生的变化：
  - 规范撤回 → 给原收件老师发**撤回通知**，新老师同步「已结案、无需办理」；
  - 补救结案 → 发**结案通知**，已结案补救不向新老师重复发放；
  - 任课变动且事项仍开放 → 给新老师发**接办通知**，原老师收到变更说明。
- `recipients` 未登记的新任课老师在路由中标记 `routable=false`，需补录后再分发。
- 系统只生成本地分发包，不接真实邮箱。

## 6. 简报排程与两期差异

- `editions.prepared` 是排程备好日，`send_day` 是实际分发日。名单备好后未发出前
  发生补交、任课变动或认领裁定的，**当次分发按 send_day 的新事实重新核定**，
  同时输出 `prep_to_send_changes` 保留备好口径与发出口径的全部差异。
- 两期间的每条变化必须归入且只归入三类依据之一：
  - **任务构成**：观察期新结束、重开延长、新配对进入观察点；
  - **规范改判**：批准文件到达/撤销/裁定、冲突爆发或解除、要求被更正撤回；
  - **教学行为与补救**：步骤实际发生或补传、补救认领与裁定结案、任课组织变动。
- 若两期发送日之间冲突「爆发又解除」、两端快照都看不到挂起状态，引擎逐日扫描
  适用性并把相关条目标注为规范改判，保证督导能从差异追溯到文件依据，
  而不是只拿到一个更新后的百分比。
